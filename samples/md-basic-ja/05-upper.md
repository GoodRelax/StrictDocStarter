## 要求の書き方 - EARS

**Type**: SECTION

本書と `06-lower.md` の要求は、 すべて **EARS** の 5 つの型のいずれかで書いてある。
EARS は要求文の形を 5 つに絞る書き方であり、 条件の書き忘れと、 1 つの文へ複数の
要求を詰め込むことを防ぐ。

| 型 | 形 | 原型 (英語) |
|---|---|---|
| 遍在型 (Ubiquitous) | 〈システム〉は、〈応答〉すること。 | The `<system>` **shall** `<response>`. |
| 事象駆動型 (Event-driven) | 〈トリガ〉したとき、〈システム〉は、〈応答〉すること。 | **WHEN** `<trigger>`, the `<system>` **shall** `<response>`. |
| 状態駆動型 (State-driven) | 〈状態〉の間、〈システム〉は、〈応答〉すること。 | **WHILE** `<state>`, the `<system>` **shall** `<response>`. |
| 望ましくない挙動型 (Unwanted behaviour) | もし〈条件〉ならば、〈システム〉は、〈応答〉すること。 | **IF** `<condition>`, **THEN** the `<system>` **shall** `<response>`. |
| 任意機能型 (Optional feature) | 〈機能〉を備える場合、〈システム〉は、〈応答〉すること。 | **WHERE** `<feature>`, the `<system>` **shall** `<response>`. |

**英語の原型を併記したのは、 EARS の資料がほぼ英語で書かれているためである。**
型を見分ける手掛かりは、 英語では文頭の `WHEN` / `WHILE` / `IF` / `WHERE` という
1 語であり、 日本語では 「〜したとき」 / 「〜の間」 / 「もし〜ならば」 /
「〜を備える場合」 という語尾である。 **どちらも文の先頭に置く。**

**`shall` は 「〜すること。」 に当たる。** 英語の EARS が `shall` を要求、
`will` を事実の記述、 `should` を推奨として使い分けるのと同じ区別を、 日本語では
「〜すること。」 と 「〜する。」 と 「〜が望ましい。」 で付ける。 **この一式は
要求を全部 「〜すること。」 で終える**ので、 `audit.sh` の `ears-shape` は
その語尾の有無を見ている。

**条件は主語より先に書く。** これが EARS の要点である。 主語を先頭に置いて
「本ツールは、 〜の場合、 〜すること。」 と書くと、 読む側は条件に行き着くまで主語を
抱えたままになり、 条件の抜けにも気づけない。 条件を先に出せば、
**その要求がいつ効くのかが文頭で決まる。**

**この一式は EARS 専用のフィールドをあえて持たない。** 型は `**Statement**:` の文
そのものに現れる。 型名を別のフィールドに書くと、 フィールドと本文がずれたときに
どちらを信じるのかを決められなくなる。 代わりに `audit.sh` の `wording candidates`
が、 文そのものの形 (`ears-shape` と `ears-order`) を検査する。

ただし `negative` の行は消さなくてよい。 望ましくない挙動型は 「〜しないこと。」 と
書くのが正しいためである。

### 複合型 - 型を重ねる

**Type**: SECTION

**上の 5 つを重ねた 6 つめの型がある。** EARS の原典はこれを **複合型 (Complex)** と
呼ぶ。 条件が 2 つ以上あるときに使う。

```text
WHERE <feature>, WHILE <state>, WHEN <trigger>, the <system> shall <response>.
```

日本語ではこうなる。

```text
〈機能〉を備える場合、 〈状態〉の間に〈トリガ〉したとき、 〈システム〉は、
〈応答〉すること。
```

**重ねる順が決まっている。** 外側から内側へ、 **`WHERE` → `WHILE` → `WHEN` (または
`IF`)** の順に置く。 原典は複合型の雛形を
`While <precondition(s)>, When <trigger>, the <system name> shall <system response>`
と書いており、 **状態が先、 トリガが後**である。 望ましくない挙動を重ねるときは
`When` の代わりに `If ... Then ...` を使う。

| 重ねるもの | 意味 |
| --- | --- |
| `WHERE` (〜を備える場合) | **その機能を積んだ製品にだけ効く。** 製品の構成の話 |
| `WHILE` (〜の間) | **その状態が続いている間だけ効く。** 時間の幅を持つ |
| `WHEN` (〜したとき) | **その瞬間に効く。** 時間の幅を持たない |
| `IF ... THEN` (もし〜ならば) | 望ましくない入力や状況に効く |

**★ 重ねるのは 2 つまでにすること。** 3 つ重ねた文は、 読む側が条件の組み合わせを
数え上げられなくなる。 **3 つ要るなら、 それは要求が 2 つに分かれる合図である。**

この一式には複合型の例が無い。 対象が単純で、 重ねる必要が出なかったためである。
**必要になったときだけ使うこと** — 型を増やすこと自体には価値が無い。

## 既存ファイルの保護

**UID**: SYS-003 \
**STATUS**: Reviewed \
**REVIEW_STATUS**: Open

**Statement**: もし出力先に同名のファイルが既にあるならば、 本ツールは、 そのファイルを上書きしないこと。

**Rationale**: 無警告で既存ファイルを潰すと、 利用者は取り返しのつかない操作に気づけない。 既定は安全側に倒す。
